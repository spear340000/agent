## 목적과 성공 기준

Workfolio를 Manus에서 착안한 차분한 AI 문서 작업 공간으로 만든다. 요청·참고 자료·실제 작업 상태를 문서와 함께 확인하면서 결과를 편집하고 내보낼 수 있어야 한다. 시안의 정보 위계와 문서 중심 구성을 구현하되 Manus의 브랜드·로고·정확한 화면 복제는 하지 않는다.

성공 기준:

1. 제품명은 화면과 브라우저 메타데이터에서 Workfolio로 일관된다.
2. 완료 문서는 넓은 편집 캔버스에서 검토하고 변경 사항을 기존 백엔드에 저장할 수 있다.
3. 요청, 첨부 자료, 실제 진행 상태, 오류·취소 상태 및 후속 요청은 기존 백엔드 데이터와 동작에 계속 연결된다.
4. Markdown 및 DOCX 내보내기는 실제 산출물 또는 현재 편집 내용을 사용한다.
5. 데스크톱과 모바일에서 핵심 동선이 잘리지 않고 접근 가능한 조작이 가능하다.
6. 장식용 그래프·가짜 진행률·가짜 사용자 데이터·동작하지 않는 툴바는 없다.

## 사용자와 주요 흐름

일반 사용자가 문서 작성 요청과 파일·링크를 제출하고, AI가 진행하는 동안 상태를 확인한 뒤 결과를 직접 검토·수정·저장·다운로드한다.

새 작업 흐름은 현재 Composer를 유지한다. 작업을 만들면 해당 작업 공간으로 전환하고, 백엔드 작업 상세와 SSE 이벤트를 반영한다. 문서가 아직 없으면 결과 영역에 실제 상태에 맞는 대기·진행·오류 안내를 보여준다. 문서가 준비되면 문서 중심 레이아웃을 연다. 기존 후속 요청, 취소, 재실행, 파일 업로드, 출처 열람, 저장, Markdown/DOCX 다운로드 동작은 유지한다.

## 화면 구조와 반응형 동작

### 데스크톱

1. **탐색 레일:** Workfolio 브랜드, 새 작업, 기존 작업 목록 및 필터. 현재 작업 선택과 이력 조회는 기존 기능을 유지한다.
2. **작업 컨텍스트 패널:** 실제 사용자 요청, 첨부 파일·링크, 백엔드 단계와 상태, 취소/재실행, 추가 요청 입력을 모은다. 완료 작업에서는 보조 정보로 접을 수 있다.
3. **문서 구성 레일:** 문서의 Markdown 제목에서 목차를 파생한다. 제목이 없으면 빈 레일을 만들지 않는다. 항목 선택은 해당 문서 위치로 이동한다.
4. **문서 캔버스:** 화면의 주 영역. 실제 제목, 저장 상태, 편집/저장 및 내보내기 제어와 문서 내용을 표시한다. 문서가 없을 때는 상태에 맞는 빈·진행·오류 상태를 표시한다.

중립 배경, 기존 초록 포인트와 한글 서체를 유지하고 경계선과 모서리 장식은 절제한다. 실제 데이터가 없는 시안 속 시장 수치나 차트는 제품에 넣지 않는다.

### 좁은 화면

중간 폭에서는 탐색·컨텍스트 패널을 접거나 서랍으로 제공해 문서 캔버스에 공간을 우선 배정한다. 모바일에서는 내비게이션과 컨텍스트를 각각 접근 가능한 오버레이/접이식 영역으로 제공하고, 문서 편집 및 다운로드는 세로 흐름에서 사용할 수 있게 한다. 어떤 폭에서도 가로 화면 전체가 잘려 핵심 동작이 사라지지 않게 한다.

## 컴포넌트와 경계

- `Workroom`은 백엔드 데이터 로드, 활성 작업과 화면 상태를 오케스트레이션한다.
- 탐색 레일, 작업 컨텍스트, 문서 목차, 문서 편집 영역은 각자 표현과 로컬 UI 상태를 담당하는 작은 컴포넌트로 분리한다.
- 기존 `Composer`, `Documents`, `taskAdapters`, `src/api/workroom.ts`를 재사용한다. API 계약 또는 저장 데이터 모델은 이 UI 작업에서 변경하지 않는다.
- 새 편집기 라이브러리는 기본적으로 추가하지 않는다. Markdown을 저장 형식의 원본으로 유지하고, 툴바를 제공한다면 실제 Markdown 서식 삽입 등 동작하는 기능만 노출한다.
- 문서 변경은 `documentDirty`/저장 결과로 표현한다. 저장이 확인되지 않은 내용을 ‘자동 저장됨’으로 표시하지 않는다. 수정 중 내보내기는 현재 편집 내용을 반영한다.

## 데이터 흐름과 실패 처리

초기 진입 시 기존 capability와 작업 목록을 불러온다. 작업 선택은 상세를 갱신하고, 실행 중인 작업은 기존 SSE 구독으로 실제 단계를 반영한다. 생성·수정·후속 요청·취소·재실행·파일 업로드·문서 저장·다운로드는 기존 API 클라이언트를 계속 사용한다.

API 실패와 검증 오류는 해당 패널 근처에 원인을 알 수 있는 메시지로 표시한다. 요청 실패 시 입력 내용을 잃지 않는다. 연결이 끊기면 마지막으로 받은 상태와 재시도 가능한 동작을 명확히 표현하며, 완료/실패/취소를 진행 중으로 오인하게 표시하지 않는다. 새로고침 후에도 백엔드 작업 이력을 다시 읽고 활성 작업 SSE를 재구독한다.

## 접근성

랜드마크와 제목 계층을 유지하고, 패널 열기/닫기·탭·저장·서식 조작에 접근 가능한 이름과 키보드 포커스를 제공한다. 작업 상태는 과도한 반복 알림 없이 `role="status"`로 전달한다. 색상만으로 상태를 구분하지 않고 reduced-motion 설정을 존중한다.

## 검증

- 기존 API 및 이벤트 어댑터 테스트를 유지하고, 문서 변경·Markdown 목차·저장 실패/성공의 순수 로직 테스트를 추가한다.
- typecheck, lint, 테스트, 프로덕션 빌드를 실행한다.
- 브라우저에서 데스크톱(시안과 같은 1440×1024 기준)과 모바일 폭을 확인한다.
- 실제 백엔드에서 이미 확인된 흐름을 보존하며 UI에서 작업 생성 이후의 연결 상태, 진행 표시, 문서 편집·저장·다운로드 상호작용을 확인한다. 추가 유료 모델 요청은 필요하지 않으면 보내지 않는다.
- 선택한 시안과 실제 화면을 동일한 뷰포트/상태로 비교하고 P0–P2 시각 차이를 수정한다. 검토 산출물은 `design-qa.md`에 남긴다.

## 범위 밖

- Manus 명칭·로고·상표 요소 복제
